# Log Harian: 2026-10-06

## Masalah: Unduhan Gagal dengan Error `curl: (28) Operation timed out`
1. **Laporan & Gejala**:
   - Pengguna melaporkan kegagalan unduhan video YouTube beresolusi 4K (2160p, ~7.62 GB): *"Arknights - Endfield Sanctuary of Ink Special Program"*.
   - Status antrean menampilkan `[STATUS:ERROR_500]`.
   - Pesan kesalahan: `ERR: ERROR: [download] Got error: Failed to perform, curl: (28) Operation timed out...`.

2. **Akar Masalah (Root Cause)**:
   - **Pemaksaan `impersonate='chrome'` (curl_cffi)**:
     - `ydl_opts` sebelumnya memasang `impersonate='chrome'` secara global untuk semua unduhan termasuk stream video YouTube.
     - Pustaka `curl_cffi` pada Windows mengarahkan seluruh transfer fragmen ke libcurl.
     - Server CDN YouTube (`googlevideo.com`) tidak memerlukan bypass TLS Cloudflare. Saat memproses file berukuran masif (7.62 GB), pelambatan bandwidth / throttling per fragmen memicu batas waktu koneksi TCP bawaan libcurl (`CURLE_OPERATION_TIMEDOUT` / kode 28).
   - **Ukuran Chunk Terlalu Kecil**:
     - Pengaturan `http_chunk_size: 2097152` (2 MB) menghasilkan lebih dari 3.800 request HTTP terpisah untuk video 7.6 GB. Frekuensi request yang terlalu tinggi memperbesar probabilitas terjadinya timeout per chunk.
   - **Kegagalan Deteksi Fallback**:
     - Handler `except` sebelumnya hanya menangani `curl: (77)` (bad SSL CA), sehingga saat terjadi `curl: (28)`, sistem langsung melempar exception fatal tanpa mencoba retry dengan HTTP transport standar.

3. **Solusi & Perbaikan**:
   - **Kondisional Impersonate**: `impersonate='chrome'` dinonaktifkan khusus untuk streaming YouTube (`is_yt`). YouTube kini menggunakan transport HTTP native bawaan yt-dlp yang sangat stabil dan tahan terhadap rate-limiting Google Video.
   - **Optimalisasi Chunk Size**: `http_chunk_size` dinaikkan menjadi 10 MB (`10485760`), memangkas jumlah request hingga 5x lipat dan mencegah socket exhaustion.
   - **Parameter Ketahanan Jaringan**:
     - `socket_timeout`: 30 detik
     - `retries`: 10 kali
     - `fragment_retries`: 10 kali (mencegah kegagalan jika ada satu fragmen yang lambat/terputus)
     - `file_access_retries`: 5 kali
   - **Universal Fallback**: Handler error di [`backend/downloader.py`](file:///D:/Project/YT/backend/downloader.py) dan [`backend/parser.py`](file:///D:/Project/YT/backend/parser.py) kini menangani semua error `curl:` (termasuk timeout 28) dan otomatis mengulang download menggunakan koneksi standar.
